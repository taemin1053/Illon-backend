
## 1. 아키텍처 변경 및 개선 사항

| 개선 항목 | 기존 방식 | 개선 방식 | 변경 사유(Why) |
| :--- | :--- | :--- | :--- |
| **트랜잭션 관리** | `@Transactional` (Service/Facade 레벨) | 트랜잭션 경계 제거 & 최소화 | 외부 API 통신 시 DB 커넥션을 점유하여 발생하는 **커넥션 풀 고갈(Starvation)** 방지 |
| **성능 최적화** | 개별 API 호출 (N+1 발생) | Facade + Caffeine 캐싱 | 외부 네트워크 I/O 병목 제거 및 응답 속도 최적화(0.01초 단위) |
| **JPA 설정** | OSIV (Open Session in View) 활성 | `spring.jpa.open-in-view=false` | 트랜잭션 종료 시 즉시 커넥션 반환을 보장하여 시스템 부하 최소화 |
| **데이터 조회** | 프로필/유저 별도 조회 | `left join fetch` (1-Query) | DB N+1 쿼리 문제를 해결하여 조회 효율성 증대 |

## 2. API 상세 스펙 및 연동 가이드

### ① 마이페이지 통합 조회 (`GET /api/mypage`)
* **기능:** 유저 프로필 정보와 스크랩 목록(6개 페이징)을 한 번에 통합 반환.
* **사용 기술:** `MyPageFacade`를 통한 도메인 서비스 조율 및 DTO 캡슐화.
* **연동 방법:**
  ```http
  GET /api/mypage?page=0&size=6

### ② 오늘의 스크랩 현황 (`GET /api/scraps/status`)

* **기능:** 메인 홈 대시보드 통계 데이터 반환.
* **응답 구조:**
```json
{
  "newJobsCount": 0,
  "expiringJobsCount": 0,
  "totalScrapsCount": 0
}

```



### ③ 스크랩 토글 (`POST /api/jobs/{jobId}/scrap`)

* **기능:** 북마크 저장 및 취소(Toggle).
* **기술적 특징:** 공고 상세 정보는 저장하지 않고 참조 ID만 관리하여 **'단일 진실 공급원(Single Source of Truth)'** 원칙 준수.

## 3. 핵심 아키텍처 설계 의도

1. **커넥션 풀 고갈 방어:** 외부 API 통신 시 DB 커넥션을 쥐고 있으면 트래픽 증가 시 시스템 마비 위험이 큽니다. 트랜잭션 경계를 철저히 격리하여 이를 방어했습니다.
2. **Facade 패턴 활용:** 다양한 소스(DB + 외부 API)에서 데이터를 조합해야 하는 복잡한 로직을 Facade 서비스에서 일관성 있게 조율하여 서비스 간 결합도를 낮췄습니다.
3. **프론트엔드 최적화:** 프론트엔드가 데이터를 가공하기 위해 수행하던 반복적인 연산을 백엔드 API 단에서 캡슐화하여 렌더링 속도와 유지보수성을 향상했습니다.
